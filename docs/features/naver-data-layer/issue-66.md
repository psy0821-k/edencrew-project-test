# Issue #66 — EUC-KR 디코더를 하드코딩 매핑 대신 완성형 조합 공식으로 교체

## 시그니처

```dart
// lib/shared/utils/euc_kr_decoder.dart
import 'package:cp949_codec/cp949_codec.dart' as cp949_pkg;

/// `finance.naver.com/item/sise_day.naver` 응답이 사용하는 EUC-KR 인코딩을
/// 디코딩합니다. `cp949_codec` 패키지(CP949는 EUC-KR의 상위 호환)를 사용해
/// 완성형 한글 전체를 안전하게 처리합니다.
final Encoding eucKr = cp949_pkg.cp949;
```

### 배경

기존 구현(`_table` 40자 하드코딩 매핑)은 테스트에서 관찰된 문자만 처리 가능해, 표에 없는
종목명/문구가 응답에 섞이면 `FormatException`으로 렌더링이 깨질 위험이 있었다. EUC-KR
완성형 한글(KS X 1001) 2,350자는 초성×중성×종성 산술 공식만으로 유니코드에 매핑되지
않는다 — 자주 쓰는 조합만 골라 자체 순서를 매긴 서브셋이라, 완전한 매핑 표가 필요하다.
직접 2,350자 표를 옮겨 적는 대신, 검증된 `cp949_codec` 패키지(CP949 전체 매핑 내장, EUC-KR
호환)를 사용한다.

### 계약 (기존과 동일하게 유지)

- 호출부(`eucKr.decode(bytes)`)는 수정 없이 그대로 동작.
- ASCII 범위(`0x00~0x7F`)는 그대로 통과.
- 완성형 한글 등 유효한 CP949 2바이트 조합은 정상 디코딩.
- 유효 범위(`0x8141~0xFDFE`) 밖이거나 매핑에 없는 조합은 `FormatException`.

## 테스트 시나리오

### eucKr (EucKrCodec → cp949 기반)

- [정상] 실측 확인된 EUC-KR 바이트(`0xB0 0xA1`)를 디코딩하면 '가'를 반환해야 한다
- [정상] 여러 글자를 포함한 바이트 시퀀스('날짜')를 디코딩하면 원문과 일치해야 한다
- [정상] ASCII 문자(영문/숫자/기호)가 섞인 바이트를 디코딩하면 그대로 유지되어야 한다
- [정상] 기존 40자 매핑 테이블에 없던 임의의 완성형 한글(예: '삼성전자'의 '삼', '증')을
  디코딩해도 정상적으로 유니코드 문자를 반환해야 한다
- [예외] 유효 범위를 벗어난 바이트 조합(`0xFF 0xFF`)을 디코딩하면 `FormatException`을
  던져야 한다
